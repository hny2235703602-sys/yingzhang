# 角色形象文生图模块设计

> 文档状态：模块设计，尚未实现或验证图像模型与工作流。
> 目标：把文生文阶段提取并采用的角色视觉资料，转成可审核、可版本化、可供后续分镜引用的角色参考图。
> 边界：本文只设计角色参考素材，不承诺任意图片模型、ComfyUI 工作流或视频模型都支持相同参数和参考图输入。

## 1. 目标与非目标

用户完成章节分析后，可从本章发现的角色创建或补全作品级角色视觉资料，为资料编写或生成图片提示词，执行文生图，比较候选结果，选择并保存采用的参考图。角色资料和选定图片可以跨章节复用；外貌、服装和参考图的修改保留历史版本。

本模块解决的是“为角色建立稳定、可管理的视觉参考”，不是让生成图片自动成为原文事实。人物档案中的身份、关系、经历不直接作为绘图事实；当前状态（例如伤势、污渍）不自动固化为长期外观。

第一版不做：场景图和关键帧批量生成、训练 LoRA 或角色模型、自动人脸识别、自动合并疑似重复角色、自动评价候选图的剧情正确性、自动覆盖已采用素材、保证跨模型或跨镜头角色一致，以及未经验证的视频图像条件输入。

## 2. 在现有流程中的位置

```text
章节正文与可选前情
  → 文生文分析，提取角色及原文依据
  → 用户采用或编辑角色视觉资料
  → 选择基础外观与服装版本
  → 编译角色参考图提示词
  → 文生图任务生成候选图片
  → 用户审核、选定并保存素材版本
  → 后续章节与分镜按角色/服装版本引用
```

文生文运行使用创建时保存的角色视觉资料快照。之后生成的图片和更新的角色资料不会悄悄改写旧运行、旧分镜或历史提示词。只有用户显式创建新运行或更新镜头引用后，后续结果才采用新版本。

当前工作台已有作品级 `VisualProfile`，文生文分析可提出角色建议，用户可以采用建议；`visual_profiles` 保存其版本。文生图导航当前是未接入占位页。实施时应扩展这些已有边界，不另建平行的角色资料体系。

## 3. 资料来源与可信度

提示词编译前将资料按来源区分：

| 类别 | 示例 | 使用规则 |
| --- | --- | --- |
| 原文明确 | 黑色长发、左眉有疤 | 可描述为稳定特征，并保存段落依据 |
| 已采用角色资料 | 用户已确认的眼睛、身形或常服 | 可作为本次生成的固定约束 |
| 改编设定 | 原文未说明但为成图所需的发色、年龄感、鞋履 | 显示为补充设定，可编辑；不能标成原文事实 |
| 服装版本 | 校服、战斗装、礼服等 | 绑定单独版本；一次任务只选定一个目标版本 |
| 临时状态 | 本场景受伤、衣服破损、雨水打湿 | 不写入基础外观；仅在场景专用素材需求中使用 |
| 未知项 | 年龄、族裔、具体材质等无依据细节 | 保持中性或由用户明确补充，不暗中推断 |

模型生成或润色的提示词不能提升资料可信度。AI 可以把已确认属性改写成图像模型易理解的描述，但不能自行补写身份、世界观、性格事实或隐藏剧情。对于原文没有的信息，界面标记“改编设定”并允许用户确认、修改或留空。

每个可追溯事实尽量保存来源章节和原文段落 ID。当前缺少可用证据时允许创建纯视觉设定，但其 `origin` 必须是“改编设定”。

## 4. 用户流程与界面

### 4.1 入口

从文生文工作区“本章分析与角色资料”中的角色行进入“生成参考图”；文生图导航则提供全作品角色素材管理和任务历史。入口携带 `work_id`、`character_id` 和当前资料版本，避免用户重复选择角色。

### 4.2 生成设置

生成前提供以下可编辑信息：

- 角色名称及稳定 ID（只读展示 ID，名称可编辑）。
- 已确认外貌、不可变识别特征和来源。
- 目标服装版本；默认选择当前采用版本，不混合多个服装。
- 画风、画幅、背景简洁程度、姿势/视图组合等图像配置。
- 自动编译出的正向提示词和可选负向提示词；若工作流不支持负向提示词则隐藏。
- 图片数量、尺寸、种子等参数，仅展示当前图像配置实际支持的选项。

默认角色设定图采用简洁背景、清晰全身视图和面部细节；多视图拼版只在实际工作流能稳定生成且结果可辨时启用。它们是配置模板，不在提示词中同时要求互相冲突的镜头、多个场景或服装。一次任务聚焦一个角色和一个服装版本，避免属性串混。

生成前显示最终提示词、配置名称和将使用的角色资料版本。提示词可以手工修改；手工修改创建该生成任务的提示词快照，不反写角色资料。已存在生成任务时，重复点击应复用相同请求或提示用户打开任务，显式“重新生成”才创建新尝试。

### 4.3 候选审核

任务完成后按候选图展示缩略图、查看原图、下载、生成参数、种子（有返回时）、提示词版本和执行状态。用户可以选定一张或多张图为参考素材；多张素材可以有用途标签，例如“正面主参考”“侧面”“表情参考”。第一版不自动把相似图归并，也不默认把所有候选图加入提示词输入。

审核动作包括：采用为当前角色版本参考图、作为新外观/服装版本的参考图、删除未采用候选。覆盖当前资料引用属于版本更新：新增版本并保留旧版本和历史引用，不覆盖旧文件。删除操作只允许清除没有任何引用的候选；已采用素材需先解除引用，并遵循文件引用检查规则。

## 5. 角色参考图提示词编译

分开保存模型无关的生成意图与图像模型提示词。建议的语义输入包括：

```text
画风与媒介
+ 角色稳定身份特征（仅视觉描述）
+ 目标服装版本
+ 视图/姿势布局
+ 背景与光照要求
+ 角色一致性约束
+ 明确排除的冲突属性（仅在配置支持时）
```

提示词编译器读取角色资料快照、服装版本、图像生成配置和提示词模板版本，输出模型适配请求。编译结果保存为不可变快照，并计算摘要。修改任一输入后生成新摘要；旧任务不被覆盖。

生成前做确定性校验：角色 ID 和资料版本存在；选择的服装版本属于该角色；无冲突的服装或发色设定；必需提示词非空；画幅、尺寸、批量数和种子在已配置能力范围内；输出目录由系统分配而不是模型指定。无法解决的冲突需用户处理，不通过静默删改属性掩盖。

提示词模板与实际图像模型能力绑定版本。不能假定所有模型都接受英文提示词、负向提示词、种子、结构化图像参数或多视图排版。模板需用代表角色和提示词做实测后启用。

## 6. 数据对象与持久化边界

### 6.1 新增逻辑对象

| 对象 | 关键字段 | 职责 |
| --- | --- | --- |
| ImageGenerationProfile | profile_id、provider、protocol/workflow、model、能力标记、超时、重试和输出配置 | 描述已验证的图像生成入口；凭证仅保存环境变量名 |
| CharacterImageRequest | work_id、character_id、visual_profile_version、costume_version、prompt_snapshot、config_snapshot、input_hash | 冻结一次生成的全部有效输入 |
| ImageGenerationTask | task_id、状态、幂等键、尝试 ID、远端任务 ID、错误码、时间 | 支持异步执行、恢复和任务可见性 |
| ImageAsset | asset_id、文件元数据、mime_type、尺寸、sha256、角色/版本引用、用途 | 管理候选图和已采用参考图 |
| CharacterReferenceSet | character_id、视觉资料版本、服装版本、asset_id 列表、用途 | 确认哪些素材作为哪个版本的角色参考 |

`VisualProfile` 继续保存角色外貌、服装及来源等领域资料。实现时可扩展其版本化数据以引用参考素材，也可用引用表表达关系；应避免把图片 Base64 或大块像素数据存进 SQLite JSON 字段。图片文件放在配置的数据目录下，数据库存稳定 ID、相对存储键和元数据。

数据库迁移由 Alembic 管理。稳定外键和唯一约束保护作品、角色、版本、任务及资产关系。请求快照与资产引用在同一事务中建立；文件写入用临时文件和原子替换，完成后再提交可见的资产元数据。若数据库提交失败，遗留临时文件由受控清理流程处理，不能递归删除未经核对的路径。

### 6.2 资产目录

按不可变 ID 组织，不以中文角色名作为唯一文件名，例如：

```text
data/assets/characters/{work_id}/{character_id}/{asset_id}.png
data/assets/characters/{work_id}/{character_id}/{asset_id}.webp
```

实际扩展名依据经过校验的输出 MIME 类型确定。检查文件签名、允许格式、大小和解码尺寸；拒绝路径穿越、超限图片和不支持的格式。服务端生成最终路径，模型返回的文件名不得直接控制文件系统路径。备份和项目导出需包含已采用素材及其元数据；候选素材是否纳入备份可配置，但默认应与数据库一致可恢复。

## 7. 任务状态、幂等与恢复

任务状态建议为：`pending`、`submitting`、`queued`、`running`、`succeeded`、`failed`、`unknown`、`cancel_requested`、`cancelled`。状态变更集中校验。`unknown` 表示远端是否接受或完成无法确认，不能直接当作失败并重提。

- 创建任务前保存请求快照和 `pending` 状态；执行器领取任务后记录尝试 ID 与租约。
- 提交远端前持久化 `submitting`。收到远端 ID 后保存并进入 `queued`；响应丢失时先查询支持的队列/历史接口，无法核对则设为 `unknown`。
- 相同幂等键和相同输入摘要返回现有任务；同键不同摘要报冲突。用户选择重新生成时创建新尝试，保留旧结果。
- 进度断连不等于任务失败；恢复时优先核对远端任务状态和输出，不盲目重复提交。
- 成功需同时验证远端成功状态、输出文件可读取、文件类型与尺寸合规。只收到完成事件不足以标记成功。
- 取消只有在适配器确认远端取消后才标记 `cancelled`。若底层只能全局中断，禁止把该操作包装成单角色任务取消。
- 重试预算和退避策略由图像配置决定。认证、缺模型、缺节点、无效参数等确定性错误不自动重试；连接中断和暂时性服务错误可有限重试。可能重复收费或重复执行时要明确记录。

角色参考图任务与章节文生文、未来的视频生成任务分别持久化状态。Streamlit 页面刷新只查询任务，不创建新执行器或自动提交；独立执行器处理长任务，避免占用页面请求。若图像生成与本地语言/视频模型共享设备资源，必须依据实际部署能力设计串行策略，不假设资源自动释放。

## 8. 图像服务适配边界

应用层只依赖 `ImageGenerator` 能力接口，输入为已校验的不可变请求，输出为远端任务标识、状态和候选资产流/元数据。适配器负责服务商协议、ComfyUI 工作流字段映射、状态查询、错误分类和能力声明；领域和 UI 不接触节点 ID 或供应商响应结构。

第一版落地顺序：

1. 先实现手工提示词编辑、角色参考资料、文件资产管理和模拟适配器，打通任务/候选审核的数据流程。
2. 获取用户实际使用且可验证的图像工作流或服务信息，确认模型、输入字段、输出格式、队列查询和取消能力。
3. 根据实际接口实现一个适配器；连接测试、单图样例和断点恢复通过后，才在配置页标记为可用。
4. 不把“ComfyUI 已有视频工作流”当作“已有图像工作流”；不假定视频节点可用作文生图。

配置保存 provider、protocol/workflow 版本、模型标识、服务地址、密钥环境变量名、支持的画幅/尺寸/种子/批量/负向提示词能力及超时策略。真实密钥只在执行时读取，不写入 SQLite 任务快照、导出包、检查点或日志。适配器只收发当前角色生成需要的角色描述和提示词，不上传整章小说；如该任务确需原文依据，也应在界面明确展示实际发送内容。

## 9. 与分镜和视频阶段的衔接

生成角色图片本身不会自动改变分镜。每个镜头的角色引用应包含角色 ID 和视觉资料/服装版本；需要参考图时，增加具体的 `reference_image_ids` 或等价稳定资产 ID。提示词编译器只把用户选择且当前镜头适用的素材交给视频适配器。

只有当已验证的视频工作流确实支持图像输入后，才启用“将角色参考图用于视频”能力。该适配需要确认图像输入节点、尺寸/裁切要求、图像权重或同等参数、文件传输路径和输出效果。工作流不支持时，仍可在 UI 展示和人工下载参考图，但不能声称角色一致性已增强。

参考图新增或角色资料变更时，找出引用旧版本/旧素材的分镜并标记“可复核/需显式更新”，不能自动重生成视频。重新生成提示词或图像结果会创建新版本和新任务，旧结果仍可查看。

## 10. 安全、隐私与成本

- 小说正文和模型输出均是不可信数据，不能更改系统提示、选任意文件路径或触发工具调用。
- 对图片执行 MIME/文件签名、大小和解码维度校验；输出路径限制在配置的资产根目录内。
- 日志默认不记录小说全文、完整生成提示词、密钥或原始图像字节。诊断模式需显式开启并定义清理期限。
- 若调用线上图像服务，向用户清楚表明发送给哪类配置的服务方和发送的数据范围。不得自动回退到另一个服务商。
- 不在配置缺少有效定价时伪报成本；可记录服务商返回的任务 ID、用量或费用字段，未知值保留为未知。
- 为批量尺寸、分辨率、文件大小和同时运行数设有配置上限；限制来自已验证部署能力，不在多个层重复硬编码。

## 11. 实施阶段与验收

### 阶段 A：领域资料与本地资产

明确角色/服装版本、来源和采用关系；支持候选素材元数据与本地文件校验、引用和版本展示。无需调用真实模型。

验收：能够保留原文事实与改编设定的来源差异；更新角色或服装不会覆盖旧引用；非法 MIME、超限尺寸和路径穿越被拒绝。

### 阶段 B：请求与任务闭环

实现提示词编辑/快照、profile 能力检查、任务幂等、独立执行器接口、状态展示、候选审核和显式重做；使用模拟图像适配器验证恢复行为。

验收：刷新页面不重复提交；同请求命中已有任务；响应丢失进入 `unknown` 并优先核对；明确重做生成独立尝试；失败时已完成角色资料不丢失。

### 阶段 C：接入一个真实图像工作流

以用户目标机器上的真实图像服务/ComfyUI 工作流为准，完成字段映射、错误分类、输出验证和代表性角色样图测试。记录实际模型、配置、耗时、费用信息（如服务返回）和样图结果。

验收：至少覆盖一次成功、一次无效配置/缺模型、一次中断恢复；成功素材能打开、能绑定角色版本并从新章节查询。模拟测试不作为真实模型接通证据。

### 阶段 D：视频参考图验证

针对实际视频工作流单独验证参考图输入和样片效果。通过后再启用镜头级图片引用，否则该能力保持不可用状态。

## 12. 测试重点

- 角色、作品和外观/服装版本隔离，来源字段与证据引用校验。
- 提示词快照和输入摘要覆盖 profile、模板、角色版本、服装版本及生成参数。
- 重复点击、相同键冲突、显式重做、任务状态合法转换和并发执行器领取。
- 远端接受但响应丢失、队列查询、断线恢复、租约过期和未知状态处理。
- 返回非图片、伪造 MIME、损坏文件、超限像素和文件写入中断。
- 资产引用保护、版本更新、删除检查、数据库事务与原子文件发布。
- 凭证和提示词日志脱敏、线上数据范围、服务商错误分类与有限重试。
- 视频阶段只接收已选择且适用于目标镜头的素材；不支持参考图的模板必须阻止误传。

自动测试模拟外部图像服务，不调用真实模型。真实图像质量和视频角色一致性均需在目标环境独立验收。
